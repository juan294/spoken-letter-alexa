## Summary

The skill accepts a few named playback and catalog intents plus free text. It sends most requests to `/agent/turn`; the agent can list, fetch, or suggest delivered stories through three read-only MCP tools. A device session uses a service subject that resolves to fixtures, even in `auto` provider mode. The skill plays one story per `AudioPlayer.Play` directive, can resume, restart, or repeat its current token, and answers playback events without a follow-up action. There is no playlist state or account-write path in this repository. These observations follow the skill routing (`packages/skill/src/handler.ts:135-159`, `packages/skill/src/handler.ts:198-268`), the agent routes (`packages/agent/src/routes.ts:142-179`), the tool registry (`packages/mcp-server/src/tools/index.ts:10-12`, `packages/mcp-server/src/tools/index.ts:63-105`), and provider routing (`packages/mcp-server/src/provider/registry.ts:10-25`).

## Request and data path

1. The Lambda handler checks the Alexa application ID, handles launch and playback controls locally, maps supported intents to one text line, and sends that line with the opaque device user ID to the agent (`packages/skill/src/handler.ts:187-259`). The skill client opens or reuses a `device` session and posts to `/agent/turn`; an expired session is reopened once (`packages/skill/src/agent-client.ts:34-95`).
2. The agent hashes the device user ID into a stable session ID, retains conversation history for two hours, and refreshes a cached story catalog after 15 minutes (`packages/agent/src/sessions.ts:5-25`, `packages/agent/src/sessions.ts:41-55`). The device route obtains a service token, reads the catalog through MCP, and runs a Strands turn with that catalog (`packages/agent/src/routes.ts:142-179`).
3. The agent exposes `say` and optional `play` as structured output (`packages/agent/src/schema.ts:4-22`). Its persona says to list and fetch stories before returning a recording, and to answer catalog questions without playback (`packages/agent/src/persona.ts:1-12`). The MCP surface registers only `list_family_stories`, `get_family_story`, and `suggest_next_story` (`packages/mcp-server/src/tools/index.ts:10-12`, `packages/mcp-server/src/tools/index.ts:63-105`).
4. The provider contract contains story ID, title, storyteller, duration, delivery time, optional art, and audio URL. It contains no recipient, sender email, family space, wish, feedback, event, credit, or draft operation (`packages/mcp-server/src/provider/types.ts:1-28`). Fixture stories are sorted newest first and exposed as MP3 URLs (`packages/mcp-server/src/provider/fixtures.ts:54-90`). The HTTP provider has two bridge operations, listing delivered stories and obtaining an audio URL (`packages/mcp-server/src/provider/http.ts:60-93`).
5. A `device` session uses a service token (`packages/agent/src/routes.ts:145-148`, `packages/agent/src/routes.ts:167-170`). `svc:*` subjects resolve to fixtures in `auto` mode, as does every subject in `fixtures` mode (`packages/mcp-server/src/provider/registry.ts:10-25`). Thus a current classic-skill device request does not reach an account-specific private catalog; this is an inference from those two routing rules, not a live-device measurement.

## Current recovery and visibility

When the agent client times out or rejects, the handler asks the speaker to try again; it logs the outcome and error class (`packages/skill/src/handler.ts:63-68`, `packages/skill/src/handler.ts:260-293`). When the agent itself cannot produce valid structured output or throws, it returns a fixed “can't reach” message and no audio (`packages/agent/src/turn.ts:124-137`, `packages/agent/src/schema.ts:29`). Missing playback context is spoken for resume or previous, while playback events themselves produce no spoken response (`packages/skill/src/handler.ts:108-114`, `packages/skill/src/handler.ts:198-220`). A stale catalog is refreshed on a later device session open; a failed refresh leaves the prior catalog or falls back to a tool call (`packages/agent/src/sessions.ts:50-55`, `packages/agent/src/routes.ts:87-105`, `packages/agent/src/routes.ts:153-155`).

Amazon's current [AudioPlayer reference](https://developer.amazon.com/en-US/docs/alexa/custom-skills/audioplayer-interface-reference.html), retrieved 2026-09-28, describes playback progression events and `ENQUEUE` with `expectedPreviousToken`. It also says a `PlaybackFinished` response cannot carry `outputSpeech`, a reprompt, or another `Play` directive. A feedback question therefore cannot simply be spoken in that event response. Amazon's [Proactive Events overview](https://developer.amazon.com/en-US/docs/alexa/smapi/proactive-events-api.html), retrieved 2026-09-28, describes customer-specific notifications using predefined schemas and customer notification permission. These are platform capabilities, not claims that this skill uses them.
