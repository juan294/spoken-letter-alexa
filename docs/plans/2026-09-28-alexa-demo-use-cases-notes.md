## Phase 1: playback journeys

Local implementation is committed as `cac8309a2fd81e180ba6637f6b4572a2417df804`. The skill uses an authenticated internal playlist command route. The controller reads delivered stories through the existing MCP tools, fetches fresh audio before playback, persists only hashed device keys, story IDs, positions, token digests and event digests with a two-hour TTL, and uses conditional writes for stale callback races. Skill audio supports `ENQUEUE` with `expectedPreviousToken`; new stream tokens are short and opaque. Generated `en-US` intents route all, newest, creator, title, replay and playlist reset requests. Model replies without audio cannot claim playback. Raw slot values, catch-all speech and model `say` are excluded from skill telemetry.

## Deviations

- **First-20 catalog bound.** The direct-title oracle broadly says to play a unique delivered title. The MCP list tool returns at most 20, so a title outside that window cannot be resolved on this route. The main plan's stuck-state contract explicitly requires a bounded-list explanation for 21 or more stories. The controller now says it checked the first 20 and offers an available title; it does not claim the requested story is absent from the account. This remains a deliberate demo limit pending a separately designed paged catalog contract.
- **Raw utterance recording.** The earlier UX implementation could record catch-all text and optional model speech. The phase's no-child-name log invariant makes those raw values unsafe for this path. Skill telemetry keeps intent and slot names, but omits slot values, catch-all text and model speech. The older recording controls therefore produce no raw training utterances in this implementation.

## Phase 2: guided demo draft and app handoff

Local implementation is committed as `21b81ab`. A dedicated authenticated route saves at most ten two-hour demo drafts per hashed device key in a separate DynamoDB table. The request ID is hashed for idempotency. Speech selects one of seven canonical themes; only that theme reaches Bedrock and the store. Bedrock selects enum outline components and the server renders a bounded, name-free outline. The skill asks for a missing theme, supports readback, and says a draft was saved only after the conditional write succeeds. Named-listener requests and credit requests give the private-app handoff without a write or a claim of delivery or payment. The generated `en-US` model adds creation, theme, help-topic, and readback intents. The three public MCP tools remain read-only.

Independent review found that a pending draft initially treated any catch-all text as a theme. A playback request with “forest” could therefore save an unintended draft. It also found that catch-all creation help asked for a theme instead of giving app steps. Both branches were repaired and covered by red-then-green tests; the reviewer passed the focused re-review. The local simplify pass retained one authenticated client path and reused the existing conditional-store pattern.

## Phase 3: fixture wishes, reactions, updates, and notification path

Local implementation is committed as `5897e00`. The authenticated demo routes keep completion, reaction, confirmed wish, and event state in a bounded seven-day record keyed separately from drafts by a hashed device ID. `AudioPlayer.PlaybackFinished` records the first completion from either an opaque playlist token or a validated direct-play fixture token; it returns no speech. The next invocation prompts for like/love once; a successful conditional write saves a demo reaction tied to the delivered story ID and adult storyteller. A confirmed, canonical-topic wish is saved in the fixture inbox without contacting the storyteller. Generic family-occasion and new-story fixture events are validated at startup. Spoken new-story detail names the exact validated fixture title; events are marked read when a skill response is prepared for speech or explicitly dismissed.

The manifest declares `AMAZON.MessageAlert.Activated`, subscription changes, and the notification permission. A dedicated subscription Lambda stores the opted-in Alexa user ID as KMS ciphertext in a separate TTL table; an unsubscribe replaces the ciphertext with a tombstone, and older events cannot restore it. A separate IAM-only sender Lambda accepts only a bundled fixture event ID, checks opt-in, reads external skill credentials, requests the `alexa::proactive_events` token, and calls only Amazon's development endpoint with generic, stable-reference payload. It has no automatic trigger. No event was sent.

Independent review found five gaps: direct-play completions were missed; the development sender had no executable entry point; new-story detail lost the fixture ID; skill creator resolution was hard-coded; and reaction records omitted the adult creator alias. All were repaired and the reviewer passed the final local source review. The simplify pass reused the authenticated client request helper for drafts and playlist calls.
